Experiment 01 · Local fault classification

REPRODUCIBLE

The edge node runs a nearest-prototype classifier. Each sensor frame is normalized into a 3-D feature vector, its Euclidean distance to five class prototype vectors is computed, and the nearest class is emitted. The model has 15 parameters (0.6 KB), runs in O(k·d) per frame and needs no accelerator or network access.

1. Sensor busTemperature · vibration · current
→
2. NormalizeScale inputs to comparable ranges

3. ClassifierDistance to class prototypes

4. Safety logicThreshold interlock + alarm

Feature vector

x = [temperature / 120, vibration / 1.5, current / 10]

Normalization maps sensor channels to similar numeric ranges. This prevents a large-number channel from dominating distance purely because of its units.

Distance function

d(x, c) = √ Σ (xᵢ − cᵢ)²

The class prototype with the smallest Euclidean distance is selected. The displayed score maps distance to a 50–99 similarity scale: s = 100 · (1 − d / 1.25).

Safety separation: the model predicts a class; an independent emergency interlock activates at 110 °C. The interlock path is evaluated before the model output and cannot be overridden by it.

Test protocol

  1. Start with the normal-operation preset.
  2. Run inference and record the predicted class and latency.
  3. Repeat for overheating, excess vibration, high current and combined fault.
  4. Run the threshold baseline on the same readings.
  5. Compare predictions and discuss failure cases.
  6. Use the evaluation tab to compute metrics from the deterministic test set.

Expected observations

  • Inference is available without network requests.
  • Different sensor patterns can produce different class predictions.
  • Threshold rules are easy to explain but can miss combinations or trigger on one noisy signal.
  • Prototype-based classification separates combined faults that single-channel thresholds mislabel.
  • Per-frame inference latency stays well under 1 ms.

Technical report

EdgeGuard AI: Edge-Based Industrial Motor Fault Detection

Abstract. This project demonstrates an edge-computing architecture for industrial motor monitoring using temperature, vibration and current sensing on a Raspberry Pi 4 class node. A local nearest-prototype classifier predicts the motor operating state and an independent interlock enforces an emergency stop. The classifier is benchmarked against a threshold-rule baseline on a labelled 25-sample set. The system demonstrates local inference, multi-sensor fusion and fully offline operation.

1. Problem statement

Industrial equipment can develop thermal, mechanical or electrical faults. A cloud-only monitoring architecture may depend on network availability and communication latency. Edge computing places processing closer to the data source so that predictions and responses can be made locally.

2. Objectives

  • Model a Raspberry Pi 4 sensor node with DS18B20, ADXL345 and ACS712 inputs.
  • Classify machine states using multiple sensor features.
  • Demonstrate local inference and offline-capable behavior.
  • Compare a prototype classifier with threshold rules.
  • Measure per-frame inference latency.

4. Methodology

The node acquires sensor values, normalizes the three features and computes Euclidean distances to five class prototypes. The nearest prototype provides the predicted class. A separate threshold baseline identifies faults using fixed limits. A critical-temperature interlock activates independently at 110 °C. A fixed labelled benchmark is used to calculate accuracy and confusion matrices for both methods.

5. Results

Run the evaluation tab to populate this section.

6. Edge AI advantages demonstrated

  • Low communication dependence: predictions do not require a server request.
  • Low latency: sub-millisecond inference per frame.
  • Privacy: sensor data never leaves the node.
  • Resilience: local inference can continue when a network is unavailable.

7. Design decisions

A nearest-prototype model was chosen for its tiny footprint, deterministic behavior and direct interpretability: every prediction can be explained by its distance to each class. Safety is enforced by a hard interlock that is independent of the classifier, so a misclassification can never prevent an emergency stop.

8. Future scope

Fit prototypes from field-recorded sensor logs, add an anomaly score for unseen fault types, export a compact model to TensorFlow Lite Micro for microcontroller targets, and publish telemetry over MQTT for fleet dashboards.

9. Conclusion

EdgeGuard AI provides a hands-on demonstration of the edge inference workflow: local sensor processing, classification, event logging and local alert behavior. It also benchmarks the model against a rule baseline on a reproducible labelled set and keeps safety logic independent of the model.
